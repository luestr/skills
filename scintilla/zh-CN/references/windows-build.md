# Windows 构建与诊断

## 构建要求

官方文档要求支持 C++17；Windows 可使用 GCC 7.1 或 Microsoft Visual C++ 2017.5 及更新版本。确认目标架构（x86/x64/ARM64）、运行库、导出符号和宿主位数一致。

## DLL 与静态库

动态链接通常使用 Scintilla `.DLL`。静态链接使用 `bin/libscintilla.lib`（GCC 可为 `.a`），并在宿主中调用 `Scintilla_RegisterClasses(HINSTANCE)`。独立 DLL 应编译 `ScintillaDLL.cxx`，提供 `DllMain` 与 `Scintilla_RegisterClasses`。

## 常见构建宏

| 宏 | 用途 |
|---|---|
| `NO_CXX11_REGEX` | 不使用 C++11 `std::regex` |
| `SCI_OWNREGEX` | 使用自定义 regex engine，并实现 `RegexSearchBase`/factory |
| `SCI_DISABLE_AUTOGENERATED` | 禁用自动生成常量或宏 |
| `SCI_DISABLE_PROVISIONAL` | 禁用 provisional features |
| `INCLUDE_DEPRECATED_FEATURES` | 暴露 deprecated features |
| `DISABLE_D2D` | Windows 上禁用 Direct2D/DirectWrite |

## 排错清单

1. “窗口类找不到”：检查 DLL 加载、`Scintilla_RegisterClasses`、模块句柄和调用时机。
2. 文本乱码：确认 Scintilla 编码、传入 byte 长度、NUL 规则，不要把 UTF-8 长度换算成 code point。
3. 补全无 lexer：确认 Lexilla 部署、lexer 名称、加载路径和 `SCI_SETILEXER`。
4. DLL 加载失败：用依赖查看器检查架构、运行库和缺少的依赖；不要只替换 DLL 而保留旧 headers/import library。
5. dirty 状态异常：检查 `SCI_SETSAVEPOINT` 及 save-point notifications 是否与文件保存事务一致。
6. 崩溃或随机文本：检查 `SendMessage` 的指针类型、缓冲区容量、GUI 线程和临时指针生命周期。
