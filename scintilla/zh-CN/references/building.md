# Building Scintilla 构建矩阵

官方构建要求支持 C++17。Windows 可使用 GCC 7.1 或 Microsoft Visual C++ 2017.5；GTK 使用 GCC 7.1 或更新版本，GTK 2.24/3.x 需要对应 glib。实际版本、依赖和命令以源码目录中的 README 为准。

## Windows

动态使用通常是 `.DLL`；独立 DLL 编译 `ScintillaDLL.cxx` 提供 `DllMain` 和 `Scintilla_RegisterClasses`。静态链接 `bin/libscintilla.lib`（GCC 可为 `.a`）后，由宿主调用 `Scintilla_RegisterClasses(HINSTANCE)` 注册窗口类。DLL、headers、import library 和宿主架构必须匹配。

## GTK、Cocoa、Qt

源码也支持 GTK、Cocoa 和 Qt。构建脚本会检测 GTK 版本；同时存在 GTK 2/3 时构建 GTK 3 定义 `GTK3`。Qt 的平台行为与 Windows DLL 不等价，v5.6.4 的 pixel-aligned fractional scaling 是 Qt 相关变更，不应泛化为 Windows 能力。

## Regex 和宏

- `NO_CXX11_REGEX`：不使用 C++11 `std::regex`。
- `REGEX_MULTILINE`：启用 C++11 multiline regex。
- `SCI_OWNREGEX`：实现 `RegexSearchBase` 和 `CreateRegexSearch`，替换内置 regex。
- `SCI_DISABLE_AUTOGENERATED`：禁用自动生成常量/宏。
- `SCI_DISABLE_PROVISIONAL`：排除 provisional API。
- `INCLUDE_DEPRECATED_FEATURES`：暴露 deprecated features。
- `DISABLE_D2D`：Windows 禁用 Direct2D/DirectWrite。
- `PTRDIFF_DOESNT_ALIAS_INT`：遇到相关指针别名编译错误时使用。

增加或删除源码文件可能需要修改 build files；源码中的 `AddSource.txt` 说明了相关步骤。构建完成后验证导出符号、窗口类注册、Lexilla 配套版本和目标架构。
