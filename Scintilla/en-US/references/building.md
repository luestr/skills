# Building Scintilla

The official build requires a C++17-capable compiler. Windows can use GCC 7.1 or Microsoft Visual C++ 2017.5; GTK uses GCC 7.1 or newer with GTK 2.24/3.x and the corresponding glib. Use the source README for the current dependency and command details.

## Windows

Dynamic use normally produces a `.DLL`; a standalone DLL compiles `ScintillaDLL.cxx` for `DllMain` and `Scintilla_RegisterClasses`. Static linking uses `bin/libscintilla.lib` (`.a` with GCC), after which the host calls `Scintilla_RegisterClasses(HINSTANCE)` to register the window class. DLL, headers, import library, and host architecture must match.

## GTK, Cocoa, and Qt

The source also supports GTK, Cocoa, and Qt. Build scripts detect GTK; when both GTK 2 and GTK 3 are installed, define `GTK3` for GTK 3. Qt behavior is not equivalent to the Windows DLL; v5.6.4's pixel-aligned fractional scaling is Qt-specific and must not be generalized to Windows.

## Regex and definitions

- `NO_CXX11_REGEX`: build without C++11 `std::regex`.
- `REGEX_MULTILINE`: enable C++11 multiline regex.
- `SCI_OWNREGEX`: implement `RegexSearchBase` and `CreateRegexSearch` to replace the built-in regex.
- `SCI_DISABLE_AUTOGENERATED`: disable autogenerated constants/macros.
- `SCI_DISABLE_PROVISIONAL`: exclude provisional APIs.
- `INCLUDE_DEPRECATED_FEATURES`: expose deprecated features.
- `DISABLE_D2D`: disable Direct2D/DirectWrite on Windows.
- `PTRDIFF_DOESNT_ALIAS_INT`: use when pointer-alias compilation errors require it.

Adding or removing source files may require build-file changes; `AddSource.txt` documents the process. After building, verify exports, window-class registration, the matching Lexilla release, and target architecture.
