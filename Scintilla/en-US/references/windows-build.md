# Windows build and diagnostics

## Build requirements

The official documentation requires a C++17-capable compiler; Windows builds can use GCC 7.1 or Microsoft Visual C++ 2017.5 and newer. Match target architecture, runtime library, exports, and host bitness.

## DLL and static library

Dynamic integration normally uses the Scintilla `.DLL`. Static integration uses `bin/libscintilla.lib` (`.a` with GCC) and calls `Scintilla_RegisterClasses(HINSTANCE)`. A standalone DLL should compile `ScintillaDLL.cxx` to provide `DllMain` and `Scintilla_RegisterClasses`.

## Build macros

| Macro | Purpose |
|---|---|
| `NO_CXX11_REGEX` | Build without C++11 `std::regex` |
| `SCI_OWNREGEX` | Use a custom regex engine and implement the required interface/factory |
| `SCI_DISABLE_AUTOGENERATED` | Disable autogenerated constants or macros |
| `SCI_DISABLE_PROVISIONAL` | Build without provisional features |
| `INCLUDE_DEPRECATED_FEATURES` | Expose deprecated features |
| `DISABLE_D2D` | Disable Direct2D/DirectWrite on Windows |

## Troubleshooting checklist

1. “Window class not found”: check DLL loading, `Scintilla_RegisterClasses`, the module handle, and call timing.
2. Garbled text: verify Scintilla encoding, byte lengths, and NUL rules; do not convert UTF-8 length to code-point count.
3. Completion has no lexer: verify Lexilla deployment, lexer name, search path, and `SCI_SETILEXER`.
4. DLL load failure: inspect architecture, runtime, and missing dependencies; do not replace only the DLL while retaining old headers/import libraries.
5. Dirty state is wrong: align `SCI_SETSAVEPOINT` and save-point notifications with the file-save transaction.
6. Crashes or random text: check `SendMessage` pointer types, buffer capacity, GUI-thread ownership, and temporary pointer lifetime.
