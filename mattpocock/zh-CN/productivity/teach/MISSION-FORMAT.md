# MISSION.md 格式

`MISSION.md` 位于工作区根目录。它记录用户学习这个主题的_原因_。每一项教学决策（接下来教什么、呈现哪些资源、设计哪些练习）都应能追溯到这份文档。

## 模板

```md
# 使命：{主题}

## 为什么
{1-3 句话。用户追寻的具体现实目标。拥有这项技能后，他们的生活或工作会发生什么变化？避免“理解 X”这类抽象说法；追问背后的结果。}

## 成功的标志
- {用户将能够做到的一件具体、可观察到的事}
- {另一件具体的事}
- {……}

## 约束条件
- {时间、预算、先前的承诺、学习偏好，任何限制做法范围的因素}

## 范围之外
- {用户明确表示眼下不想追求的相邻主题，以保护最近发展区}
```

## 规则

- **每个工作区一个使命。** 如果用户想学两件互不相关的事，那就是两个工作区。
- **具体优先于抽象。**“十月前跑完半程马拉松”胜过“变得更健康”。“给团队交付一个 Rust CLI”胜过“学 Rust”。
- **对含糊要顶回去。** 如果用户说不清为什么，先访谈他们，再动笔写任何东西。糟糕的使命比没有使命更糟。
- **现实变了就修订。** 使命会变。用户的目标移动时，更新这份文件：不要让一份过时的使命继续引导未来的会话。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它就不再是罗盘，而变成了计划。
