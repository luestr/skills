撰写任何 Agent 要读的文档时的参考：一份技能、一份 `AGENTS.md` / `CLAUDE.md`、一份经由指针触达的文档。打包方式各不相同，写法并无区别：同一组杠杆让每一份都变得可预测，因为 Agent 每次运行走的是同一个_过程_，而不是产出同样的输出。

你正在写的文档若是技能，请阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式的选择和路由技能。

## 上下文指针

**上下文指针**是 Agent 上下文里的一条引用，它指名某个上下文之外的素材，并编码了触达该素材的条件。技能的 description 是一条；`AGENTS.md` 里指名某份文档的一行是同一个东西。决定 Agent 何时触达素材、以多可靠的程度触达的，是指针的_措辞_，而不是它的目标。必备素材挂在措辞薄弱的指针后面，就是一个行为波动 bug（variance bug）：先打磨措辞，只有打磨无效时才把素材内联进来。

一条指针干两件事：说明素材是什么，并列出应当触发触达它的**分支**（分支是文档处理的一个独立情形，因此不同运行会沿不同路径穿过文档）。常驻指针的每个词每轮都要付出成本，所以它值得比正文更狠的修剪：

- **把引导词前置**：指针正是引导词发挥触发作用的地方。
- **每个分支一个触发。** 给同一个分支改名的同义词，是同一个分支写了两遍；合并它们，只保留真正不同的分支。
- **删掉正文已经交代过的身份说明。**

## 两种负载

你新增的每份文档和每条指针，都会花掉两种预算之一：

- **上下文负载**是常驻素材压在 Agent 上下文窗口上的成本：`AGENTS.md` 里的一行、一条技能 description、任何每轮都留在上下文里的东西——无论是否触发，都在消耗 token 和注意力。
- **认知负载**是压在人身上的成本：存在哪些文档，以及何时该取用哪一份。人就是索引。这不是一项要压到最低的成本：它是人类能动性的代价；在人需要判断的地方花掉它，在人不需要判断的地方移除它。

只经由指针触达的素材，用指针自身那一行的代价换来了免于上下文负载；而完全没有指针的素材，则完全靠认知负载承载。

## 信息层级

一份文档由两类内容构成：**步骤**（Agent 按顺序执行的动作）与**参考**（按需查阅的定义、规则、事实）。两者可以自由混合：全是步骤（一份菜谱）、全是参考（一份评审的规则、本技能），或两者兼有。核心决策是每一块内容在**信息层级**上的位置——一架按 Agent 对素材的即时需要程度排序的阶梯：

1. **文件内步骤**是主层级：Agent 按顺序做什么。
2. **文件内参考**按需查阅。它往往是一组合法平级的同伴（一份评审的每条规则都处在同一级），这种安排没有问题，不是坏味道。
3. **外置参考**被推到单独的文件里，经由上下文指针触达，只在指针触发时加载。它的范围从同一文件夹里的兄弟文件，一直到完全外部的参考——后者位于任何地方，任何文档都可以指向它。

往下推得太少，顶层就会臃肿；推得太多，又会藏起 Agent 真正需要的素材。这个张力就是全部决策所在。

**渐进披露**是沿阶梯向下移动（移出主文件、退到指针之后），让顶层保持清晰可读。它主要不是 token 优化：这正是保护信息层级的方式。分支是最干净的披露检验：每个分支都需要的，内联；只有部分分支会触达的，推到指针后面。当文档有步骤时，本该披露的文件内参考会埋没这些步骤，让对它们的关注变成一场抛硬币：这是一根影响行为波动的杠杆，而不只是可读性杠杆。

**就近聚合**是文件内的配套动作：阶梯决定一块内容落在_多深_的位置，就近聚合则决定它一旦落位后_旁边放什么_。把一个概念的定义、规则和注意事项收在同一个标题下，而不是散落各处，这样读到其中一部分，它的邻居也会随之而来。检验标准：文档读起来应该像为 Agent 写的文档。聚合起来的内容读起来就是这样；散落的内容则不是。（这与重复不同：重复是在两个地方重复同一个意思；散落是把一个意思切碎到许多地方。）

**蔓延**是这里的失效模式：文档就是太长了，哪怕每一行都仍然有效、独一无二。注意力在多余内容上被摊薄，而每多一行，就多一行需要保持相关性。解药就是阶梯：把参考披露到指针后面，并按分支或序列拆分，让每条路径只承载自己需要的东西。

## 步骤与完成判据

每个步骤都终结于一条**完成判据**——告诉 Agent 工作已完成的那个条件。两个属性让它成为一根杠杆：

- **清晰度**：Agent 能否分辨做完与没做完？含糊的边界（“已达成理解”）会招来**提前收尾**：在真正完成之前就结束该步骤，注意力滑向_已经做完_这件事本身。前方仍然可见的步骤（**后续步骤**）提供拉力；判据的清晰度是阻力。按顺序防守：**先磨锐边界**（局部且便宜）；只有当它模糊到无可再改_且_你确实观察到这种抢跑时，才通过拆分序列把后面的步骤藏起来。隐藏只在真实的上下文边界上有效（一次交接或一次子 Agent 派发；内联调用会把后续步骤留在上下文里，什么都清除不了）。
- **要求强度**：它要求多少。“每个被改动的模型都交代到位”逼出彻底的工作，而“产出一份变更清单”做不到这一点。要求强度驱动**功课**（Agent 在工作中做的挖掘，它潜伏在措辞里，而不是被写成独立步骤），而且它不局限于步骤：“每条规则都套用”约束的是一整块平级参考，正如“每个步骤都完成”约束的是一个序列——纯参考型文档之所以仍然带着完备性门槛，靠的就是这一点。

最强的判据既可检验，又穷尽。

## 何时拆分

把一份文档拆成两份，要花掉两种负载之一，所以只有当这个切口值回票价时才拆：

- **按序列**：把这样一串步骤拆开——其中的后续步骤会诱使 Agent 抢跑眼前这一步。把它们移出视野，会逼出在当前任务上更多的功课。警惕反过来：合并序列会让每个步骤的后续步骤暴露给接下来的内容，招来提前收尾。
- **按调用方式**（技能专属）：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**引导词**是模型预训练中已经存在的一个紧凑概念，Agent 在运行文档时用它来思考（_课程_、_战争迷雾_、_曳光弹_）。它以 token 的形式反复出现，从不以整句出现，从而累积出一个分布式的定义，并用最少的 token 锚定一整片行为区域——靠的是调动模型已有的先验。自己造词也行，前提是你把它定义清楚；但生造的词调动不了任何先验：预训练词免费给你的东西，你得用定义用的 token 来买单；优先去找已有的词。

它锚定两次。在正文里，锚定_执行_：只要这个词出现，Agent 每次都会取用同一套行为；在平级参考内部，它把注意力聚焦到一类值得寻找的东西上。在指针里，锚定_调用_：当同一个词同时生活在你的提示词、你的文档和你的代码库中时，Agent 会把这种共享语言与素材联系起来，更可靠地触达它。

主动寻找用引导词重构的机会。一个在三个地方逐字铺开的三元组；一条花一整句话去比划某一个概念的指针。每一处都是一段文字，在恳求收拢成单个 token：

- “fast, deterministic, low-overhead” → _tight_（一条 _tight_ 回路）。
- “a loop you believe in”（一个你信得过的回路）→ _red_，把一道模糊的闸门变成二元可观察状态（回路在 bug 上变_红_，或者没有）。

你会赢两次：token 更少，以及一个更锋利的钩子，供 Agent 把思考挂上去。假定每份文档都带着一些可以被引导词淘汰的重述。去找出来。

**否定式表述**是这根杠杆旁边的失效模式：用禁令来引导，会把被禁止的行为拖进上下文，让它变得_更加_可用，而不是更少。_别去想大象_，于是满脑子只剩大象；否定是个弱修饰词，会被强烈激活的概念淹没，于是这条禁令有一半读起来像是在指示去做那件事。要用**正向表述**：说出目标行为（“写单行注释”），被禁的那种就永远不必出场。禁令只有在作为一种你无法正向表述的硬护栏时才值得留下；即便如此，也要把它和正向目标配在一起，让注意力落在该做的事上。

## 修剪

- 让每个含义都有**单一事实来源**：唯一一个权威位置，这样改变行为只需改一处。**重复**（同一个含义出现在不止一个地方）要付出维护和 token 的代价，还会把一个含义在阶梯上的显著度抬到超出它真实的位置。（它是引导词的无意反面——引导词有意重复一个 token，从不重复含义。）
- **环境**也是一个事实来源（`package.json` 脚本、配置文件、目录结构、`--help` 输出），而重述环境的文档是一份**缓存**：一次查询结果的副本，只有当这次查询昂贵时才值回它的负载。只缓存 Agent 靠看找不到的东西：未写下来的约定、某个选择背后的原因、任何配置都不会明说的坑。一文件、一命令就能查到的内容，留给环境——在那里它们不会过期。
- 逐行检查**相关性**：它是否仍然关系到文档要做的事？一行失去相关性，要么因为从未与任务相关（纯属铺陈，或者一个本该披露出去的分支），要么因为它描述的行为或世界变了、它过时了。文档越短，越容易保持相关性。没有修剪纪律，默认的结局就是**沉积层**：一层层过时的东西沉淀下来，因为增加感觉安全、删除感觉冒险，直到你必须往下打钻，才能找到还活着的内容。
- 逐句猎捕**无效果指令（no-op）**：一条模型默认就会遵守的指令，白付负载什么也没说。这个检验（相对于默认行为，它是否改变了行为？）是相对于模型、而非相对于读者的：两个人对某条指令是不是无效果有分歧，其实是对默认行为有分歧，解决办法是运行这份文档，而不是辩论。一句话没通过检验时，删掉整句，而不是从里面剪几个词。这个检验同样给引导词评级：一个弱到压不过默认行为的词（当 Agent 本来就挺彻底时，_要彻底_）就是无效果指令，修法是换一个更强的词（_不留情面_），而不是换一种技巧。
