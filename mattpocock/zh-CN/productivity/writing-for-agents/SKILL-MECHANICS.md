# 技能机制

[`writing-for-agents`](SKILL.md) 的技能专属分支：当文档是技能时，什么会变（frontmatter、调用方式的选择，以及路由技能）。其余关于写作的内容，都是 `SKILL.md` 里的通用参考。

## 调用方式

两种选择，权衡的正是那两种负载：

- **模型自动调用**的技能保留 `description`，这样 Agent 能自主触发它，其他技能也能触达它。你仍然可以键入它的名字：模型调用总是_包含_用户可达；description 只会增加 Agent 的发现能力，从不夺走人的可达性。description 是技能的顶层上下文指针，被迫始终加载：用永久的上下文负载换取可发现性。内容全是参考的模型自动调用技能，也是共享参考的一个去处：另一个技能可以调用它，于是多个技能共用的参考只存放在一处。机制：省略 `disable-model-invocation`，写一条面向模型的 description，携带触发的分支（`SKILL.md` 里的指针写法规则完全适用）。
- **用户手动调用**的技能把 description 从 Agent 的可达范围里剥掉：只有人类键入它的名字才能调用，其他技能都不行。上下文负载为零，但它花费认知负载：你就是那个必须记得它存在的索引。机制：设置 `disable-model-invocation: true`；`description` 转为面向人类：一句话摘要，触发列表一律剥离。

只有当 Agent 必须自己触达该技能、或另一个技能必须触达它时，才选择模型自动调用。如果它只会被手动触发，就设为用户手动调用，不付任何上下文负载。

两个用户手动调用的技能都需要的共享参考，两边都住不了：没有 description，两者都无法触发对方。把它推到技能系统之外的一个普通文件里：任何技能都能指向的外部参考。

## 按调用方式拆分

拆分中的调用切口（序列切口见 `SKILL.md`）：当你有一个独特的引导词应当单独触发某个技能（一个你在提示词里确实会用的触发词），或另一个技能必须触达它时，就把它拆成一个模型自动调用的技能。你要为新的常驻 description 支付上下文负载，所以这种独立可达必须值这个价。

## 路由技能

当用户手动调用的技能多到你记不过来时，堆积的认知负载由**路由技能**来治：一个用户手动调用的技能，点名其他技能以及各自何时取用，这样人只需记住一个技能，而不是许多个。它只能提示，永远不能触发它们：用户手动调用的技能没有 description，所以除了人以外，什么都触达不到它们。
