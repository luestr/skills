# 向导

**向导**是一个 bash 脚本，带人一步步走完一套手工流程——这套流程亲手做很烦，每次都重新向 AI 讲一遍也很烦。它会打开每个 URL，明确说出要点哪里、复制什么，收集这些值，把它们写到该去的地方（`.env`、GitHub secrets），在每个阶段都要求确认，并显示还剩几个阶段。它可能配置第三方服务、执行一次性迁移，或把项目从一种状态搬到另一种状态。

令人愉悦的 UX 已经由 [template.sh](template.sh) 解决：逐阶段的进度、确认关卡、跨平台打开 URL（包括 WSL）、隐藏式密钥输入、幂等的 `.env` 更新插入、`gh secret`/`gh variable` 写入，以及收尾总结。**你的工作只有界定流程并编写它的阶段。** `STAGES` 标记以上的库在每个向导里都完全相同；这种一致性正是重点：永远不要手工编辑它。

向导默认是一次性的：为一次运行而构建，保存到临时路径或 `scripts/` 路径，任务完成后删除。只有当用户希望有一条可重复、应当留在仓库里的设置流程时，才提交它。

## 流程

### 1. 界定流程

梳理出人类必须做的每一个手工步骤，以及过程中会收集的每一个值。先读仓库，不要空手就问：

- 设置场景：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置，以及 `.github/workflows/*`（每一处 `secrets.*` / `vars.*` 引用都是向导必须产出的值）。
- 迁移或过渡场景：当前状态、目标状态，以及两者之间不可逆的操作。

然后向用户展示按顺序排列的阶段列表，以及每个阶段产出的值，并请他们确认：他们可以增加、删除或调整顺序。

**完成判据：** 每个阶段都按顺序命名，并且对每个收集的值你都知道：（a）人类从哪里获得它；（b）它被写到哪里（`.env`、GitHub secret、两者都写，或哪里都不写——有些阶段是纯操作）；（c）它是密钥（隐藏输入）还是公开值。

### 2. 梳理每个阶段的路径

对每个阶段，写出人类要走的精确路径：打开哪个 URL、在那里做什么、值显示在什么地方、它填入哪个变量：例如“Dashboard → Developers → API keys → Reveal test key → copy”。如果你并不真正了解当前的 UI 或确切命令，就如实说明，去问用户或查文档：绝不要编造可能并不存在的步骤。

**完成判据：** 每个阶段都能落到一个陌生人也能照着做的具体指令上。

### 3. 编写向导

把 `template.sh` 复制到目标路径。按依赖顺序，把示例阶段替换为每个步骤一个 `stage`。使用库里的辅助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。把 `TOTAL_STAGES` 设为实际编写的阶段数。

守住模板设定的标准：先打开 URL 再询问它的值；凡是密钥一律用 `ask_secret`；每个需要持久化的值都用 `write_env`；只对 CI 真正需要的值用 `set_secret`；任何不可逆操作之前都要 `confirm`。每个 `stage` 都会清屏，让屏幕上只保留当前步骤：让一个阶段只做一件聚焦的事，这样人类需要的信息就不会被滚出屏幕。不要碰标记以上的库。

### 4. 验证并交接

- `bash -n <script>`；`shellcheck` 可用就运行它。
- `chmod +x <script>`。
- 不要自己把它从头到尾跑一遍：它会打开浏览器，并阻塞等待人类输入。改为静态走查：第 1 步里的每个值都被收集，并且落到第 1 步说的位置；每个 `set_secret` 的名字都与 CI 中的某个 `secrets.*` 引用完全一致。
- 告诉用户怎么运行它。如果这是一条可重复的设置流程，就提交它，并在 README 里链接它，这样下一个人会直接运行脚本，而不是去问 AI。
