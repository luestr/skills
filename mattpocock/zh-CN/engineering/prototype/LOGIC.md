# 逻辑原型

一个单一的、自包含的 HTML 文件（一个**可分享的演示**），让任何人都能通过点击按钮来驱动一个状态模型。当问题关乎**业务逻辑、状态转换或数据形态**时用它：这类东西在纸上看着合理，只有拿真实场景跑一遍才会发现不对劲。

因为它是一个文件、什么都不用装，你可以把它交给非开发者（设计师、PM、领域专家），让他们自己去感受这个模型。所以它说他们的语言，而不是代码的语言。

## 什么时候该用这个形态

- “我不确定这个状态机能不能处理先 X 再 Y 这种边界情况。”
- “这个数据模型真的能表达……这种情况吗？”
- “我想先摸清 API 应该长什么样再动手写。”
- 任何有人想**按按钮、看状态变化**的场合。

如果问题是“这个应该长什么样”，那就是走错了分支。用 [UI.md](UI.md)。

## 流程

### 1. 写明问题

写代码之前，先写下你要原型化的是哪个状态模型、哪个问题。一段话，放在演示的顶部（放在可见的引言里，而不只是一段注释）。逻辑原型如果回答错了问题就是纯浪费，所以要把问题写明确，方便之后核对——无论用户是现在就盯着，还是离开键盘（AFK）之后再回来看。

### 2. 把逻辑隔离在一个可移植的模块里

把真正的逻辑（回答问题的部分）写进单个 `<script>` 块，做成一个小巧的纯模块，之后可以整个拎出来放进真实代码库。它周围的页面是一次性的；这个模块不是。

合适的形态取决于问题：

- **一个纯 reducer**：`(state, action) => state`。适合操作是离散事件、状态是单一取值的情况。
- **一个状态机**：显式的状态与转换。适合“此刻哪些操作才算合法”本身就是问题的一部分。
- **一组小型的纯函数**，作用于一个普通数据类型。适合没有隐含的当前状态、只有变换的情况。
- **一个方法面清晰的类或模块**，适合逻辑确实拥有持续的内部状态时。

选最贴合所问问题的形态，*而不是*最容易接到页面上的形态。保持纯粹：不碰 DOM、不碰 `document`、按钮处理器不伸进去。页面调用它；没有反向流动。这正是原型在自己生命周期结束后仍然有用的原因：问题一旦回答完，验证过的 reducer／状态机／函数集可以自己拎进真实模块。

### 3. 构建可分享的 HTML 文件

一个文件，纯 HTML/CSS/JS：不用框架、不用打包器、不用服务器，全部内联，双击就能打开，用邮件传来传去也没问题。任何人打开它就应该能跑起来。

为非开发者而写。每个标签都用**领域语言**，而不是代码：按钮和状态读起来像业务，而不是像 reducer。用大白话解释正在发生什么。

用清晰的层级自上而下排布：

1. **标题和一行说明**，讲清这个演示让你探索什么（第 1 步里的问题）。
2. **当前状态**：完整的相关状态，渲染成可读的面板（带标签的字段，而不是原始 JSON 转储），每次点击后重新渲染，让变化可见。在有助于非开发者跟上的地方，指出刚刚变了什么。
3. **自由试玩按钮**：每个操作一个按钮，始终可用，任何人都能按任意顺序摆弄模型。每次点击派发对应操作并重新渲染状态。
4. **引导式演练**：一组**场景**，每个标签页一个。每个标签页里有一段简短的大白话场景描述（它设定的情境、要留意什么），下面是为该场景排列好的**要按的按钮**。每个步骤都是真按钮：点击它执行该操作并前进到下一步。开始一次演练会重置到已知的初始状态，让场景每次都按同样的方式跑。

挑选能展示那些别扭情况的场景——纸上难以推理的那些：正常路径、棘手的边界情况、一次按设计不该被允许的尝试。

做得好看但克制：干净的排版、充裕的留白、一个强调色。不要动画，不要花招：任何会跟状态和按钮抢注意力的东西都不要。

### 4. 交出去

把文件发给他们，或者替他们打开。他们有空的时候会点完演练和自由试玩；有意思的时刻是他们说“等等，这不应该发生”或者“咦，我以为 X 会不一样”的时候；那些是_想法_里的 bug，而这正是重点。如果他们想要新的操作或新的场景，就加上。原型会演化。

### 5. 留下答案和原型

原型回答了它的问题之后，先记下答案，然后按 [SKILL](SKILL.md) 描述的方式把原型留存下来。逻辑原型对应的映射：验证过的 reducer／状态机／函数集拎进真实模块（决策，被吸收）；HTML 外壳随原型一起挪到一次性分支上，让原型继续作为一手资料——而且它就是一个自包含文件，在那里重新运行毫不费力。

## 反模式

- **不要加测试。** 需要测试的原型就不再是原型了。
- **不要把它接到真实数据库上。** 用内存状态，除非问题明确是关于持久化的。
- **不要泛化。** 不要“万一以后要支持 X 呢”。原型只回答一个问题。
- **不要把逻辑和页面混在一起。** 如果纯模块引用了 DOM、`document` 或按钮处理器，它就不能再被拎出来了。让页面只是纯模块外面的一层薄壳。
- **不要动用框架、打包器或服务器。** 收件人双击打开的一个文件；React 应用或开发服务器会让“可分享”失效。
- **不要把 HTML 外壳发布到生产。** 这个页面是为手工点击而优化的。它背后的逻辑模块才值得保留。
