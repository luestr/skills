一个粗略的想法已经到来，它大到超出单个 Agent 会话的容量，还裹在迷雾里：从这里到**目的地**的路还看不见。寻路要做的就是找到这条路，而不是径直冲向目的地。本技能把这条路**绘制**成仓库 issue 跟踪器上的一张**共享地图**，然后一次一张地处理它的**决策工单**（解决方式是做出决策的问题，而不是可执行构建的切片），直到路线清晰。

目的地因任务而异，命名它是绘制地图的第一个动作：它塑造每一张工单。它可能是一份要交接出去并反复迭代的规格说明，一个要在规划开始前锁定的决策，或一项就地做出的改动，比如数据结构迁移。地图与领域无关：工程工作、课程内容，凡是符合这个形态的都可以。

## 只规划，不动手

wayfinder 默认是**规划**：每张工单解决一个决策，当路线清晰、在有人去把事情做掉之前不剩下任何待决事项时，地图就完成了。想直接动手做事的冲动，通常就是信号：你已经到了地图的边缘，该交接了。任务可以在它的**备注**里覆盖这一点，把执行一并带进地图本身；但没有这一条时，产出决策，不要产出交付物。

## 用名称指代

每张地图和每张工单都是一个 issue，因此都有**名称**：就是它的标题。在人类读到的一切内容里（叙述、地图的已定决策），都用这个名称来指代，绝不用裸 id、编号或 slug。一整面 `#42, #43, #44` 的墙无法辨读；名称一眼就能读懂。id 和 URL 并没有消失；名称包裹着自己的链接，但它们是待在名称_内部_的，绝不代替名称。

## 地图

地图是此仓库 issue 跟踪器上的单个 issue，标签为 `wayfinder:map`，是规范产物。它的工单都是地图的子 issue。

地图是**索引**，不是存储。它列出已经做出的决策，并指向持有细节的工单；一个决策只存在于一个地方——它的工单，所以地图从不重述决策，只概括要点、给出链接。

**地图、它的子工单、阻塞关系和前沿查询具体存放在哪里，由跟踪器决定。** issue 跟踪器应该已经提供给你。如果没有，让用户运行 `/setup-matt-pocock-skills`。查阅跟踪器文档的“寻路操作”一节，了解_本_仓库如何表达这些内容。如果未提供跟踪器，默认使用 local-markdown 跟踪器。

### 地图正文

整张地图的低分辨率视图，每个会话加载一次。未关闭的工单**不**列出：它们是通过查询找到的未关闭子 issue。

```markdown
## 目的地

<到达这张地图终点时是什么样子：这项任务正在寻路抵达的规格说明、决策或改动。一两行；每个会话在挑选工单之前都先以此为参照。>

## 备注

<领域；每个会话都应查阅的技能；这项任务的常设偏好>

## 已定决策

<!-- 索引：每个已关闭工单一行，足以判断相关性，然后顺着链接深入工单所承载的细节 -->

- [<已关闭工单标题>](link)：<答案的一句话要点>

## 尚未明确

<!-- 见“战争迷雾”：范围内、暂时还开不成工单的迷雾；随着前沿推进而转化 -->

## 范围之外

<!-- 见“范围之外”：被判定在目的地之外的工作；已关闭，永不转化 -->
```

### 工单

每张工单都是地图的**子 issue**；跟踪器的 issue id 就是它的身份。它的正文是那个问题，规模控制在单个 100K token 的 Agent 会话之内：

```markdown
## 问题

<这张工单要解决的决策或调研>
```

每张工单带一个 `wayfinder:<type>` 标签，取值是 `research`、`prototype`、`grilling`、`task` 之一（见[工单类型](#工单类型)）。`wayfinder:` 标签是地图及其工单唯一携带的标签，绝不用 `ready-for-agent` 这类分诊标签：它们是决策，不是实现工作。

会话**认领**一张工单的方式，是在做任何工作**之前**先把它指派给驱动地图的开发者，这样并发的会话就会跳过它。那个被指派的人_就是_认领本身：未关闭且未指派的工单就是未被认领的。

阻塞使用跟踪器的**原生**依赖关系：这一点至关重要，因为它能在跟踪器自己的 UI 里_可视化_地呈现前沿，让人不用打开地图就能看到哪些工单可以接手。只有缺少原生阻塞能力的跟踪器才退回到正文约定。当阻塞某张工单的每张工单都已关闭时，这张工单就是**无阻塞**的；**前沿**是未关闭、无阻塞、未被认领的子工单，是已知的边界。

答案不属于正文；它在工单解决时被记录下来（见[沿着地图推进](#沿着地图推进)）。解决工单过程中创建的资产从 issue 链接过去，而不是粘贴进去。

## 工单类型

每张工单要么是 **HITL**（human in the loop，人在回路，_与_一个能为自己发声的人类一起处理），要么是 **AFK**，完全由 Agent 独自驱动。HITL 工单只能通过这种实时交流来解决；Agent 绝不代替人类的那一侧（一个自问自答的拷问 Agent 已经破坏了这个规则）。

- **Research**（AFK）：阅读文档、第三方 API 或知识库之类的本地资源，找出某个决策正在等待的事实。由一个调用 Skill 工具（传入 “research”）的子 Agent 解决。需要当前工作目录之外的知识时使用。
- **Prototype**（HITL）：制作一个便宜、粗糙、具体的产物（提纲、粗略方案、stub，或 UI/逻辑代码）供人直接反馈，以此提高讨论的保真度，做法是调用 Skill 工具（传入 “prototype”）。把原型作为资产链接进来。当关键问题是“它该长什么样”或“它该怎么表现”时使用。
- **Grilling**（HITL）：对话。默认情况。始终调用 Skill 工具两次，分别传入 “grilling” 和 “domain-modeling”。
- **Task**（HITL 或 AFK）：必须先完成、然后才能做出_决策_的手工工作：没什么可决策、可原型或可调研的，但讨论在它完成之前一直受阻。注册一个服务以便评判它的 API、开通访问权限、搬运数据以便看清它的形态。这是唯一“做事”而不是“决策”的类型，它靠解除某个决策的阻塞来赢得自己的位置，而不是靠交付目的地。Agent 能独自驱动时就独自驱动（AFK）；否则就把一份精确的检查清单交给人类（HITL）。工作完成时即解决；答案记录做了什么，以及后续工单所依赖的任何事实（凭据位置、新 URL、行数）。

## 战争迷雾

地图是_有意_不完整的：看不清的东西就不要绘制。在现有工单之外，是**战争迷雾**：那些你能感觉到即将到来、却还无法确定的决策和调研的模糊轮廓，因为它们取决于仍未解决的问题。解决一张工单会清除它前方的迷雾，把此刻可以明确的东西一张一张地转化为新工单，直到通往目的地的路线清晰、不再剩下任何工单。

地图的**尚未明确**小节就是写下这幅模糊轮廓的地方：疑似的问题、以后要重新审视的区域。它是_朝向_目的地的未发现前沿：这里的一切都在范围内，只是不够清晰，开不成工单。按视野允许的程度随意或详尽地写；它同时也是路标，让协作者读到这项任务正走向何方。

**是迷雾还是工单？**判断标准是你现在能否精确地陈述这个问题，_而不是_你现在能否回答它。

- **开成工单**，当问题已经足够清晰时——即使它被阻塞、你还无法处理它。
- **放进尚未明确**，当你还无法把它表述得那么清晰时。不要预先把迷雾切成工单大小的块：迷雾比工单更粗糙，当前沿抵达它时，一小块可能转化为好几张工单，也可能一张都不转化。

**尚未明确**要排除的：已经决定的（已定决策）、已经是现有工单的，以及范围之外的（下一节）。

## 范围之外

迷雾只会_朝着_目的地积聚。目的地确定范围，所以它之外的工作属于**范围之外**：它不是迷雾，也不属于**尚未明确**。它在地图上有自己的**范围之外**小节：你有意识地从_这项任务_中排除的工作。决定它放在这里的是范围，不是清晰度。

范围之外的工作永不转化（前沿到目的地就停），所以它只有在目的地被重画时才会回来，而且届时是一项新任务，不是续接。

判定某件事范围之外是一种界定范围的动作，不是路线上的一个步骤。当一张已经存在的工单被发现位于目的地之外时（绘制时被错误纳入范围，或被某次解决结果暴露出来），**关闭它**（已关闭的工单毫无疑问地离开前沿），并在**范围之外**小节留下一行：要点，加上它为何在范围之外，链接那张已关闭的工单。它不进入**已定决策**，那里记录的是实际走过的路线；范围边界不是路线上的一个步骤。

## 调用

两种模式。无论哪种，**每个会话解决的工单都不超过一张**，research 工单除外。

### 绘制地图

用户带着一个粗略的想法调用。

1. **命名目的地。**调用 Skill 工具两次，分别传入 “grilling” 和 “domain-modeling”，确定这张地图要寻路抵达的是什么：规格说明、决策，还是改动。目的地确定范围，所以先敲定它。
2. **摸清前沿。**再拷问一次，这次**广度优先**：在整个空间里铺开，而不是在任一线索上深挖，浮现出未决的决策和现在就可以迈出的第一步。**如果没有浮现出迷雾**（通往目的地的路已经清晰，整个旅程小到一个会话就能走完），你不需要地图。停下来，问用户想怎么进行。
3. **创建地图**（标签 `wayfinder:map`）：填好目的地和备注，已定决策留空，把迷雾草拟进**尚未明确**。
4. **创建你现在就能明确的工单**，作为地图的子 issue，然后在**第二遍**里接好阻塞关系（issue 需要先有 id 才能互相引用）。交叉引用也在这一遍里用真实 id 写好：占位符 `#<n>` 会自动链接到一张无关的 issue。接线把它们分拣进前沿和被阻塞两组；你还无法明确的一切都留在迷雾里：**尚未明确**小节。
5. **启动 research 子 Agent。**为你刚创建的每张 `research` 工单各拉起一个子 Agent，让它调用 Skill 工具（传入 “research”）并行解决该工单，把发现记录在一次性（用完即弃）的 `research/<name>` 分支上，并在工单里留下一个上下文指针。推送该分支，但不开 PR：它永远不会被合并。
6. 停下：绘制地图是一个会话的工作量；它不亲手解决任何东西。

### 沿着地图推进

用户带着一张地图（URL 或编号）调用。工单是**可选的**：没有工单时，由你挑选下一个决策，而不是用户。

1. 加载**地图**：低分辨率视图，而不是每张工单的正文。
2. 选择工单。如果用户点名了一张，就用它。否则按顺序取前沿里的第一张。**认领它**：做任何工作之前把它指派给自己。
3. 按其 `wayfinder:<type>` 标签指明的类型解决它（见[工单类型](#工单类型)）。读标签，不要只读正文：正文从不明说类型。**按需放大**：随时抓取任何相关或已关闭工单的完整正文；`## 备注` 块点名了哪些技能，就调用 Skill 工具执行哪些技能。拿不准时，调用 Skill 工具两次，分别传入 “grilling” 和 “domain-modeling”。
4. 记录解决结果：把答案作为**结论评论**发出，**关闭**该 issue，并把一个**上下文指针追加**到地图的已定决策。
5. 添加新浮现的工单（先创建、后接线）；把答案使其可以明确的迷雾全部转化掉，并从**尚未明确**里清除每一个已转化的块，让它只以新工单的形式存在。如果答案揭示某张工单（这张或另一张）位于目的地之外，就**判定它范围之外**，而不是把它作为路线上的节点去解决。如果该决策使地图的其他部分失效，更新或删除那些工单。

用户可能并行运行无阻塞的工单，所以要预料到其他会话正在并发编辑跟踪器。
